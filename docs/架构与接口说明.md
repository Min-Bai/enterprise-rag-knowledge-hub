# 架构与接口说明

## 系统架构

```text
浏览器 -> Vue 3 -> Nginx -> FastAPI -> MySQL
                              |-> Redis -> Celery Worker/Beat
                              |-> Qdrant
                              `-> DeepSeek / 外部转写服务
```

| 服务 | 职责 | 默认端口 |
| --- | --- | --- |
| frontend | Vue 构建产物托管、Nginx API 代理 | 8080 |
| api | FastAPI、认证、业务 API、数据库迁移与健康检查 | 8000 |
| worker | 文档解析、OCR/转写、切分、向量化与索引 | 内部服务 |
| beat | Celery 定时任务 | 内部服务 |
| mysql | 用户、权限、知识库、文档、会话和审计数据 | 127.0.0.1:3306 |
| redis | Celery 队列、缓存和限流 | 内部服务 |
| qdrant | 向量索引和语义检索 | 内部服务 |

代码边界：`backend/app/api/client` 提供客户端 API，`backend/app/api/admin` 提供管理端 API，`services` 负责业务逻辑，Celery 负责异步处理。MySQL 保存业务事实，Qdrant 保存向量索引；两者不能互相替代。

## 文档处理流程

```text
上传 -> 格式/大小/MIME/权限/SHA-256 校验 -> uploaded
     -> Celery -> processing -> 解析文本、OCR 或转写
     -> 切分 -> Embedding -> Qdrant 写入 -> ready
                                      `-> failed -> 修复后重试 -> processing
```

支持 PDF、DOCX、XLSX、TXT、Markdown、CSV，以及已配置能力下的图片和音频。删除文档或重建索引时必须同步清理旧向量，避免检索到已删除内容。旧 Office 格式依赖兼容解析工具；音频需要外部转写服务。

## 问答流程

```text
问题 + 知识库 + 标签/Top-K/阈值
  -> 身份与知识库权限校验
  -> Qdrant 向量召回与过滤
  -> 组装受限上下文
  -> DeepSeek 或 OpenAI-compatible 模型流式生成
  -> SSE 返回答案、保存会话并附带来源引用
```

系统通过知识库权限、来源引用、相似度阈值、Top-K 与无依据拒答降低幻觉风险，但不能承诺绝对杜绝幻觉。问题、回答、来源与反馈保存在 MySQL，以支持多轮会话和审计。

## 权限与账号模型

客户端和管理端使用独立的登录入口及 API 边界。短期 Access Token 通过 Bearer 使用，Refresh Token 仅保存在 HttpOnly Cookie 中；生产环境必须启用 Secure Cookie。CSRF、防跨用户刷新会话和后端权限校验是安全边界，前端隐藏按钮不是权限控制。

知识库角色：

| 角色 | 能力 |
| --- | --- |
| 所有者 | 管理知识库、成员、权限、文档和索引。 |
| 编辑者 | 上传、重试、删除自身权限范围内文档及重建索引。 |
| 查看者 | 查看、检索和问答，不可修改知识库内容。 |

管理员负责用户、注册申请、密码重置申请、模型配置、模型用量与成本、运行概览和审计治理。客户端注册和密码重置请求默认需要管理端审批。

## API 入口

| 类型 | 地址 | 用途 |
| --- | --- | --- |
| 客户端 API | `/api/v1/client` | 认证、个人资料、知识库、文档、会话、问答和反馈。 |
| 管理端 API | `/api/v1/admin` | 管理员认证、用户、审批、模型、运行概览、任务和审计。 |
| 客户端 OpenAPI | `/openapi/client.json` | 客户端接口的机器可读定义。 |
| 管理端 OpenAPI | `/openapi/admin.json` | 管理端接口的机器可读定义。 |
| 客户端 API 文档 | `/api/v1/client/docs` | 客户端 Swagger 页面。 |
| 管理端 API 文档 | `/api/v1/admin/docs` | 管理端 Swagger 页面。 |
| 存活检查 | `/health/live` | 进程是否存活。 |
| 就绪检查 | `/health/ready` | 依赖是否就绪。 |
| 综合健康检查 | `/health` | 数据库、Redis、Qdrant 综合状态。 |

接口的具体请求体、响应体、认证要求和状态码以运行中对应 OpenAPI 文档为准。不得根据前端页面是否显示操作按钮判断后端权限。

## 主要接口能力

客户端 API 覆盖：登录、刷新会话、注册申请、密码重置申请、个人资料、知识库及成员管理、文档上传下载重试与批量索引、标签筛选、对话、流式问答、来源引用和反馈。

管理端 API 覆盖：管理员登录、用户状态与角色、注册申请审批、密码重置审批、邀请记录、模型配置及连接测试、模型调用用量与成本统计、运行概览、任务状态、审计日志和批量删除管理记录。模型用量统计接口为 `/api/v1/admin/analytics/model-usage`。

生产前端由 Nginx 保留 `/api/v1/` 的完整路径代理给 FastAPI；旧 `/api/` 路径兼容代理会去掉 `/api` 前缀。出现路由 404 或 Nginx 502 时，应先核对 API 路径与 API 容器健康状态。
